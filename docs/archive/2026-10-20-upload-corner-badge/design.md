# Upload corner badge — implementation decisions (2026-10-20)

The user supplied one 412×20 seven-path SVG reading “EDITABLE STROKE WIDTH” with vector handles. It is a fixed bundled artboard decoration beside the earlier Shadow template; no runtime upload, font dependency, raster, filter or external request. The user chose an adjustable artboard-relative width, default 40%. The Export settings popup chooses one of four corners and independent X/Y inward distances, measured as percentages of the emitted artboard width/height.

1. **Fidelity:** store the supplied SVG as the exact asset. Validate its viewBox, seven paths and painted bounds; normalize black paint for export. A source path uses a scientific-notation coordinate; the shared path tokenizer must distinguish a number's `e` from a one-letter SVG command before any affine bake. Convert each path to scaled/translated `d` and scale the outline widths, no exported transforms. Filled text path remains fill-only; six handle paths remain stroke-only.
2. **Opt-in and history:** off by default, bottom-right, width 40%, X/Y 3%. Global numeric/corner defaults never enable unchecked icons. Checked-only mixed/all checkbox and per-icon override follow Shadow's single global undo timeline; hidden checked rows count and active unchecked rows never change. General bulk apply preserves badge/Shadow pins. Add enabled-only template hash and precise setting values to fingerprint; as-is bytes and shadow/badge-off fingerprints remain unchanged.
3. **No icon reflow:** finish the icon + Shadow placement and artboard background/stroke unification before appending badge paths. Use serialized final viewBox W/H, exact inward margins and a uniform width capped by remaining width/height. The asset can shrink to fit but requested offsets do not move. A 100% inset or precision-degenerate badge fails `no-fit`; a source-root opacity/display that would obscure the opaque graphic fails `unsupported`. Background remains first; badge above artwork.
4. **One prepared vector:** row live preview and JPEG consume the prepared SVG; clean/SVGO preserve it; built-in EPS renders its solid paths. Combining it with Shadow still has the gradient-only partial EPS outcome. No approved source or provider/helper is touched.

Acceptance evidence: red→green parser, geometry, settings, popup/undo and pipeline tests; `tsc`, lint, changed-code quality, fast/full verification; one measured append-only quality entry. Never stage `dist/index.html`, coverage, node_modules or secrets.

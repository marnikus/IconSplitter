# Experimental Getty web helper — implementation record (2026-10-29)

The user confirmed Getty authorization for their account and supplied screenshots and HTML for the ESP batch list and Create Batch dialog. No account credentials, live Getty uploads or authenticated probes were used in development. The screenshot establishes `create-batch-button`, `create-batch-dialog`, `create-batch-submission-type`, `create-batch-submission-name`, and `create-batch-confirm-button`, plus an iStock creative illustration type and `/contribute/batches/<id>` batch links. The actual upload form and receipt indicators were not supplied. Accordingly, selecting an EPS/JPG pair is attempted only after a second user confirmation and only for a unique multi-file input advertising both EPS and JPEG. If the portal does not expose that combination, the user selects files manually. No successful receipt is inferred.

This is a smaller, local interactive CLI than the asynchronous local web-server protocol proposed in `docs/archive/2026-10-29-getty-web-automation/design.md`: no HTTP endpoints, pairing, persisted job queue, headless mode, remote upload journal or background daemon. It reuses the existing staged folder, uses a fresh visible browser, and keeps the user's app credentials out of the bridge. `run_getty_web.bat` is a Windows launcher; `node tools/getty-web/run.mjs` works in an interactive terminal where Playwright Chromium runs. Actual Getty behavior, automatic selection, batch creation navigation, formats, and account access remain unverified. Upload completion and submission for inspection remain manual. Tests use fakes and do not contact Getty.

The helper validates flat EPS/JPG pairs, rejects symlinks/empty files/duplicates, caps file count and bytes, snapshots files in a private temp directory, and checks source metadata before and after copying. It displays names/sizes before confirmation, requires a second confirmation before file selection, and verifies the HTTPS origin and batch ID. It does not upload CSV or set existing app badges. Note the legacy staging flow does set a Getty badge despite only local staging; it is not evidence of receipt.

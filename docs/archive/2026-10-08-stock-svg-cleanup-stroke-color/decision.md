# Decision — opt-in transparent SVG background (2026-10-08)

**Status: agreed scope, documentation only.** In response to the design proposal
in [`design.md`](design.md) §3.3, the user rejected removing backgrounds by
default and asked for a user-selectable transparent-background option. No code
has been changed. This decision supersedes §3.3 and its related plan/acceptance
wording only; all other proposal decisions remain unchanged.

## Contract

* Add a `transparentSvgBackground` boolean to upload settings. Default `false`
  preserves today's SVG output and old stored settings. The option is available
  in global defaults and per-icon overrides, with the existing inherited/
  overridden marker, reset, bulk-apply and undo behavior.
* When enabled, omit **only the rectangle generated by the exporter** from the
  final SVG, making that SVG background transparent. Do not search for or
  delete white rectangles in the approved source artwork.
* The existing `background` color remains in force for JPEG flattening and EPS
  output. JPEG remains opaque. When the transparency option is off, the SVG
  continues to contain the configured background rectangle as it does today.
* The transparency choice affects export output and therefore belongs in the
  canonical settings field list, persisted defaults/overrides and settings
  fingerprint. A change marks the package stale and causes the normal selective
  re-export path to rebuild the SVG.

## Pipeline and tests

Keep format-specific behavior explicit: the prepared/optimized artifact used
for JPEG and EPS retains its configured backplate; only the final SVG artifact
omits that exporter-owned rectangle when the option is true. Preserve atomic
validation/commit and metadata readback. If implementation reveals that the
current artifact ownership cannot safely separate these paths, redesign the
artifact boundary before coding rather than applying a broad XML rectangle
filter.

TDD additions to `design.md` §5/§6:

1. First add red tests for both settings values: default/false preserves the
   generated SVG background; true removes only the exporter-owned rectangle.
   A white rectangle belonging to the source artwork must survive both cases.
2. Assert the JPEG is still flattened on the configured color and EPS still
   receives its configured backplate when SVG transparency is on.
3. Cover settings round-trip from existing v1 storage (missing field → false),
   per-icon override, fingerprint/staleness, UI handle and marker, reset, bulk
   apply and undo.
4. After implementation, verify the committed SVG in the real export path and
   confirm its `viewBox`, metadata namespaces, title and source bytes still meet
   the other acceptance requirements in `design.md`.

The proposed selector handles are `upload-set-svg-transparent` and
`upload-set-marker-svg-transparent`; confirm naming against the implementation
and register the final handles in `docs/current/UI_SELECTORS.md`.

# Upload (`stockUpload`) — Stock FTPS, SFTP & Getty ESP Uploader

Handles: [selectors/stock-upload](../selectors/stock-upload.md) · Invariants: [I-80, I-81](invariants/upload.md#i-80).

## 1. Strict `export/` + `export.json` discovery (`src/lib/stockupload/discovery.ts`)

When scanning a picked workspace root (or when the root folder itself is named `export`), the `"Upload"` tab includes **only** files that satisfy both conditions ([I-80](invariants/upload.md#i-80)):
1. Reside inside a folder named `export` containing a valid committed `export.json` (`timestamps.committedAt !== null`).
2. Are explicitly listed in `record.outputs.{jpg,svg,eps}` AND physically exist on disk (`size > 0`).

Unrecorded files inside `export/`, uncommitted records, and source files outside `export/` are excluded; corrupt or unreadable `export.json` files and missing recorded outputs surface explicit warnings.

## 2. Row controls, metadata re-embedding & unified general badges

- **Preview (`StockUploadPreview.tsx`)**: scales with the pinned thumbnail zoom slider (`stock-upload-zoom`), rendering available `JPEG/PNG` (revoked blob URL) first, else `SVG`, else an `EPS` badge.
- **Identity & Location**: shows `<stem>`, primary `export/` path, available formats, and `Location` (`copyFolderText`).
- **Unified row badges (`src/lib/upload/rowbadge.ts`)**: shares `iconSplitter.upload.rowBadges.v1` and global undo `uploadRowBadges` with `"SVG to upload"` via one single general badge catalog. Hardcoded stock badges (`HARDCODED_STOCK_BADGES`: `Shutterstock`, `Adobe Stock`, `Getty Images`) plus any added custom stock badges live in this same catalog and are automatically assigned to an item row (`assignNamedBadge`) as soon as a file is uploaded to that stock, filterable via `stock-filter-badge`.
- **Local metadata (`src/stockupload/metaembed.ts`)**: clicking a row expands editable `Title`, `Description`, `Tags`, `Creator`, and `Copyright` (no AI controls). `Accept & embed` validates (`validateMetadata`) and atomically re-embeds XMP/IPTC/RDF in-place into existing `export/<stem>.{jpg,svg,eps}` files before updating `export.json`.

## 3. Stock presets, Getty Images ESP rules & local-only credentials

- **Presets (`src/lib/stockupload/presets.ts`, `iconSplitter.stockUpload.presets.v1`)**: seeded with three built-in stock sites:
  - **Shutterstock** (`ftps.shutterstock.com`, port `21`, `ftps-explicit` / `AUTH TLS`, remote folder `/`, standalone `JPG` or `EPS`).
  - **Adobe Stock** (`sftp.contributor.adobestock.com`, port `22`, `sftp` SSH-2 / SFTP v3, remote folder `/`; SFTP Member ID + generated SFTP password; standalone `SVG`/`EPS`/`JPG`/`PNG`, max `45 MB`, `1–200` char title, `5–49` keywords, no `.zip` or subfolders).
  - **Getty Images** (`api.gettyimages.com`, port `443`, `esp-https` Getty ESP HTTPS API, path `/esp/submission/v1/submission_batches` for `contributors.gettyimages.com` / `esp.gettyimages.com`; sandbox host `esp-sandbox.api.gettyimages.com` with the same path). There is **no contributor FTP/SFTP**: login is the OAuth2 *password* grant against Getty's shared auth service (`authentication.gettyimages.com/oauth2/token`, historical ESP token paths on `api.gettyimages.com` as fallback) and **requires all four** credentials — ESP username + password **and** an **ESP-enabled** Getty API Key + Secret (`client_id`/`client_secret`, arranged via the Getty ESP API team; a plain developer search/download key has no ESP submission rights). Vector submissions require **paired same-basename `<stem>.eps` + RGB `<stem>.jpg`** (AI10/CS6 EPS + RGB JPEG min `1900×2800 px`, `4075×4075 px` recommended, max `50 MB`, max `50` keywords, no `.svg`/`.zip`, no generative AI). Includes one-click **`Download ESP CSV`** (`src/lib/stockupload/gettycsv.ts`: `file name,created date,title,description,country,brief code,keywords`) for `esp.gettyimages.com` and DeepMeta batch imports — the supported route when no ESP API access was granted.
- **Credentials (`src/lib/stockupload/credvault.ts`, [I-81](invariants/upload.md#i-81))**: login/username, password, and (required for `esp-https`) Getty ESP `apiKey`/`apiSecret` live **only** in IndexedDB `iconSplitter/secrets` (`stock-ftp-cred:<presetId>`, session fallback if blocked). Never written to `localStorage`, `export.json`, presets, or logs, and **never expanded** in the UI. The helper refuses an `esp-https` login with any of the four fields missing (`stage=esp-credentials`, no token request sent) instead of fabricating a `client_credentials` grant.

## 4. Multi-target transfer (`tools/bridge/{ftps,sftp,esp}/`)

- **Pinned bar**: thumbnail zoom slider, `Apply badges`, same-stem format checkboxes (`JPEG/PNG`, `SVG`, `EPS`, `ZIP` packed deterministically in memory via `JSZip` without `export.json`), multi-upload target site checkboxes, and `Upload`.
- **Confirmation & runner (`src/stockupload/runupload.ts`)**: `Upload` opens a preflight confirmation modal. Confirmed runs send files sequentially through the zero-dependency local loopback helper (`http://127.0.0.1:47391/ftps/*`, started via `run_ftp_bridge.bat` or `run_app_ftp.bat`), reusing one pooled Explicit FTPS, SFTP v3, or Getty ESP HTTPS batch session per target stock, isolating per-file errors, supporting mid-batch `Cancel`, and recording crash-safe status in `iconSplitter.stockUpload.{history,journal}.v1`.
- **Getty ESP transport (`tools/bridge/esp/client.mjs`)**: the real ESP contributor protocol — every ESP call sends `Authorization: Token token=<access_token>` (NOT `Bearer …`, the v3 customer-API scheme ESP rejects with `401`) + `Api-Key`; binaries go through Ingestion v1 multipart (initiate with `file_name` = EPS slot / `raster_file_name` = JPG slot of **one** paired contribution + `upload_bucket`, per-10 MB-chunk `authorize_chunk` by SHA-256 hex, `PUT` to the returned S3 `upload_url` with the returned headers, `ETag` collection, complete). One submission batch is created per pooled session (or the batch id in `remoteDir` is reused); contributions stay **drafts** (metadata extraction is asynchronous) — the run summary names the ESP batch id and the user reviews & submits at `esp.gettyimages.com`. `BRIDGE_ESP_CHUNK_BYTES` overrides the part size for loopback tests only.
- **Full staged diagnostics**: every ESP failure carries `stage` (`oauth-token`, `esp-batch-list`, `esp-batch-create`, `esp-ingest-initiate`, `esp-chunk-authorize`, `s3-chunk-put`, `esp-ingest-complete`, `esp-credentials`, `helper-probe`), the server HTTP status, and all server codes (OAuth `error`/`error_description`, ESP `message`/`errors`, `WWW-Authenticate`, or a body excerpt) — credential-scrubbed — to the helper console (`[bridge] … FAILED stage=… http=… code=…`), the browser console (`[stock-upload] …`), the connection-test banner/toast, the per-item history error, and the global activity log (`stocklog.ts`: `stockUpload.connection-test` / `stockUpload.upload-run`). Live Getty calls are never made by tests; `tests/helpers/fakeesp.mjs` enforces the same real protocol surface (research trail: `docs/archive/2026-10-29-getty-esp-connect/README.md`).

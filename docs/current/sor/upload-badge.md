# Upload corner badge — checked-only, artboard-relative vector

Part of [SVG to upload](upload.md). Geometry/placement lives in `src/lib/upload/cornerbadge.ts` over the supplied fixed seven-path `src/svg/templates/editable-stroke-width.svg` (412×20, “EDITABLE STROKE WIDTH” with handles). This is not editable text, a runtime-uploaded image, a filter, or a preview-only overlay. The approved source file is never rewritten. See [I-60](invariants/upload.md#i-60), [dialog selectors](../selectors/upload-dialogs.md) and the [named design note](../../archive/2026-10-20-upload-corner-badge/design.md).

## Who receives it

The Export settings popup has a **Checked icons (N)** checkbox with off/mixed/all states. Mixed adds the badge to all checked icons; all-on removes it. Hidden checked rows count; an active but unchecked row does not. One **Badge defaults** fieldset (width %, corner, X inset %, Y inset %) is the only placement control set: it edits inherited defaults and never turns on an unchecked icon or pins a checked one. Checked badge-on icons without a placement override follow those defaults; a per-icon override stays pinned. The per-icon popup offers its own checkbox, override markers and reset. Stored global `badgeEnabled:true` is ignored on read; only a validated icon override opts in. No global control writes a badge VALUE into a row (2026-10-21): the checkbox stores the icon's `badgeEnabled` flag plus an `applied` mark (`lib/upload/decorations`), so the row and its badge row read `inherited` until that row's own dialog changes the flag; the bar's “↺ Reset to defaults (N)” clears a selection's badge/Shadow pins and marks together.

Default: off; corner **bottom-right**; requested width **40%** of the final artboard width (1–100%); inward X/Y distances **3%** each (0–100%). X is measured from the selected left or right edge as a percentage of artboard width; Y from the selected top or bottom edge as a percentage of artboard height. The corner choice changes the labels accordingly.

## Placement and output

The icon (and any Shadow) is baked/restyled/fitted first; the badge is appended **last**, above the icon, after the artboard background and stroke unification. It never participates in fitting the icon or expands the artboard. The actual emitted `viewBox` (origin 0) determines W/H and exact inward margins. The supplied seven paths are uniformly scaled, preserving their 412:20 aspect: one glyph is an opaque black fill and six handle paths are opaque black 1.5-unit outlines. With **Expand strokes** on, those six handles become filled paths too and count towards `strokesExpanded`, so the badge ships without strokes. Requested width is capped by the room remaining after both offsets, so it can shrink on a shallow board; the entered offsets are never silently moved. A 100% inset, unmeasurable output at file precision, hidden/faded source root, or malformed bundled template fails preparation by name rather than clipping or omitting the badge. Root/inherited stroke paint cannot recolour its explicit black paths.

Preview and JPEG render the same prepared vector; optimized clean SVG and built-in EPS contain the opaque paths. Badge + gradient Shadow remains a partial **built-in EPS** package because EPS cannot paint the Shadow gradient, while valid SVG/JPEG still commit. Badge-off/default fingerprints and byte-for-byte as-is exports are unchanged. Only an enabled badge fingerprints the corner, full percentages and template hash, so edits mark affected packages stale.

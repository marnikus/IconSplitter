# SVG builder — template editing

Parent: [templates & presets](svg-builder-presets.md) · also: [metadata & saving](svg-builder-metadata.md) · [performance](svg-builder-performance.md) · [rebalance](svg-builder-rebalance.md) · selectors: [templates & artboards selectors](../selectors/svg-builder-presets.md).

- **Unsaved template edits** (2026-11-14, `actions/leaveguard.ts`, `actions/leave.ts`, `SvgBuilderLeaveDialog.tsx`, `SvgBuilderStageActions.tsx`): while a template is edited and the sheet's look differs from its saved look (`templateChanged`), the stage shows **↺ Reset** (back to the saved look, one undo step) and **✓ Save template** beside ↻ Reshuffle; they vanish when the look matches again (e.g. after Undo). Opening another template, an artboard row or ＋ Artboard first asks **Save** (write back, then go on) / **Discard** (go on; the template keeps its saved look) / **Cancel** (stay, edits kept; also Escape). Closing the page with unsaved edits triggers the browser's leave prompt. The stage buttons are a little bigger (36 px).
- **Artboard look inheritance** (2026-11-14, `lib/svgBuilder/lookoverrides.ts`): a final artboard draws `template look + its own overrides + its own words/hero/icons/metadata` (`artboardConfig`). While it is open, every look setting on the stage that differs from its template is stored as that artboard's override (`overridesOf`, sparse group → key → value; written back by `useArtboardSync`). Only those settings stop inheriting: a later template change still reaches every setting the artboard never changed, and never its overrides. Its words and hero are its own anyway and are never overrides. With at least one override the row shows **↺ Template N** (`builder-artboard-reset-<id>`): it drops the overrides so the artboard inherits everything again. **↺ Template (N)** in the list head (`builder-artboards-reset-look`, 2026-11-23) does it for every checked artboard in view that has overrides. Either is ONE undo step holding only those artboards (`removal.ts` `replaceSides`); an open one swaps to the template look on the stage, its icons and words untouched (undo / redo swap back). Saved as `overrides` on each artboard, read key by key (unknown groups/keys and non-plain values drop; older saves read `{}`).
- **What is being edited** (2026-11-14, `SvgBuilderEditingLabel.tsx`): the stage's top-left names it — **EDITING ARTBOARD** · name · of template X, or **EDITING TEMPLATE** · name (nothing on a free sheet). While an artboard is open, **✎ Edit main template** (beside Reshuffle) switches to editing its template (the artboard's changes are already saved). Double-click an artboard row = open it; double-click a template picture = edit it. Editing a template clears the active artboard row, so no row looks edited.
- **Gone icons** (2026-11-14, `artboardsWithout`): an icon the library no longer has (🗑 declined, removed, no longer approved) leaves every saved artboard on the next scan and at once on 🗑 (its cell stays, empty; locks and hero drop too), and opening an artboard never brings it back. The sheet never draws an icon the library does not have (no "Unavailable" box); only an approved SVG still loading or unreadable shows the dashed broken marker. Undo of a 🗑 re-approves the icon but does not put it back into other artboards.
- **Artboard drafts** (2026-11-14, `artboarddraft.ts`; `useArtboardSync` removed): an open artboard is no longer written back on every edit. Like a template, the stage is its draft: after the first change **↺ Reset** (back to the saved artboard; its look as one undo step) and **✓ Save artboard** appear beside Reshuffle (`builder-stage-artboard-reset` / `-save`). Opening another artboard, a template, ＋ Artboard or ✎ Edit main template asks **Save / Discard / Cancel** (the same dialog, naming the artboard). "Changed" compares the stage with the saved artboard ignoring key order and empty-cell names, so opening is never a change. Closing the page with a draft asks the browser's leave question; a reload reopens the artboard with the draft still on the stage (its unsaved metadata excepted). Pending use (`+N`) of the open artboard follows the stage.
- **Editing label colour** (2026-11-15): the stage label is green while a template is edited (`.bld-editing.is-template`).
- **Stage artboard strip** (2026-11-16, `SvgBuilderArtboardStrip.tsx`, `builder-artboard-strip`, items `builder-strip-<id>`): on the stage's left side, under the label, the artboards of the template being worked on (the edited template, or the open artboard's template). A click opens one for editing at once (a changed template or artboard asks Save / Discard first). The open one is marked (`aria-current`). The wheel scrolls the strip; with more than four, ▲ / ▼ (`builder-strip-up` / `-down`) step through. The fit-to-stage zoom leaves room for it. Thumbnails share one cached picture per artboard state with the list below (`artboardPicture`), so nothing is composed twice. **＋ Artboard**, a button next to the stage label, not inside it (`builder-editing-add-artboard`), adds a new artboard of that template and opens it.
- <a id="remove-and-undo"></a>**Remove and undo** (2026-11-16; templates and folders 2026-11-22: `actions/sheetlists.ts`, `lib/svgBuilder/removal.ts`, `sheetmove.ts`; history type `builderArtboards`): while an artboard is open, **✕ Remove artboard** sits beside ＋ Artboard (`builder-editing-remove-artboard`). Adding and removing artboards (here, in the list or in bulk) and removing templates (✕ on the block, or **✕ Remove (N)** in the Saved templates header — the checked templates, else the checked artboards in view, `removalScope`) are each ONE undo step, done at once (no question). A step records only what it took out and its place (never whole lists: undoing it never rewinds a later save of anything else), validated on the way back; a step recorded before 2026-11-22 with a whole artboard list still applies. A removed template takes every artboard of it. Folders are never deleted: they MOVE into `_artboard_sheets/.removed versions/<folder>~<stamp>` — a template's folder whole (template.json and the artboard folders inside); date folders left empty go, `_artboard_sheets` stays. Undo moves them back and restores the lists, Redo moves them out again; the trash goes when empty. The folders move first: with no folder open, or a failed move, nothing changes and the toast says why. Register and scans never read the trash.
- **No dead stage** (2026-11-16, `useArtboardUndo.ts`): when undo / redo takes away the artboard open on the stage, the stage moves to the most recently viewed artboard that still exists. Failing that, it opens another artboard of its template, and if none is left, the template itself (`showArtboard`). ✕ Remove does the same with the neighbouring artboard of the template (the one before it, else the next). A removed template on the stage gives way to the nearest template left (the one above first). These moves add no undo step (`showTemplate`, 2026-11-22), so one Undo brings a removal back.
- **Walk the stage** (2026-11-23, `stagenav.ts`, `actions/stagenav.ts`, `useStageHotkeys.ts`): ◀ ▶ beside 📂 Location (`builder-editing-prev-template` / `-next-template`, disabled at the ends) and the ← → keys open the previous / next template (Saved templates order); ↑ ↓ open the previous / next artboard of the template on the stage (from the template: ↓ the first, ↑ the last). No wrapping. A changed template or artboard asks Save / Discard first. The keys act only while the builder tab is shown — never while typing (fields, sliders), with a modifier held, in a dialog or the icon editor, when a focused list already used the key, or with nothing to open (the page scrolls).
- **📂 Location** (2026-11-16, `actions/location.ts`, helper `POST /open-folder` in `tools/bridge/openfolder.mjs`): a button beside ＋ Artboard (`builder-editing-location`). It opens the open artboard's folder (else its template's), or the edited template's folder, in Windows Explorer through the local helper. The full path is the opened folder's captured path + the `_artboard_sheets/…` folder (`explorerPathOf`). The helper opens only an existing folder given as a full path, starting the file manager with the path as its only argument (no shell). Without the helper or the captured path, the path is copied and the toast says why. It uses the app-wide rule: [Location](location.md).
